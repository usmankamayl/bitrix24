### Ключевые выводы (ВАЖНО для разработки)

#### 1. Коробка vs Облако — REST API

**Облако (Cloud):**
- REST API — **основной** способ разработки
- Работа через HTTP: вебхуки, OAuth-приложения
- Нет прямого доступа к файловой системе портала
- Нет возможности устанавливать PHP-модули

**Коробка (Box):**
- **D7 API** — основной способ разработки
- REST API доступен, но используется для **внешних** интеграций
- Внутренний код работает напрямую с D7-классами (ORM, сервисы, события)
- Полный доступ к `/local` и расширениям ядра

**Пример:**
```php
// В облаке (REST API)
POST https://portal.bitrix24.ru/rest/1/webhook/user.current

// В коробке (D7 API)
$user = \Bitrix\Main\UserTable::getById(1)->fetch();
```

#### 2. Структура `/local`

Правильная структура для пользовательского кода:

```
/local/
  php_interface/
    init.php              ← автоматически подключается ядром
  classes/
    Training/
      Environment.php     ← наши классы с автозагрузкой
  modules/                ← пользовательские модули
  components/             ← пользовательские компоненты
  templates/              ← пользовательские шаблоны
```

**Почему `/local`, а не `/bitrix`?**
- `/bitrix` — ядро, перезаписывается при обновлениях
- `/local` — защищённая зона для пользовательского кода

#### 3. Автозагрузка классов

В `php_interface/init.php` зарегистрирован автозагрузчик:

```php
spl_autoload_register(function ($class) {
    $classFile = str_replace('\\', '/', $class) . '.php';
    $classPath = $_SERVER['DOCUMENT_ROOT'] . '/local/classes/' . $classFile;
    if (file_exists($classPath)) {
        require_once $classPath;
        return true;
    }
    return false;
});
```

Теперь любой класс в `/local/classes/` доступен по namespace.
