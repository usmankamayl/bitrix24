# Интеграция Bitrix Framework (БУС / Б24) с внешними системами

Этот репозиторий содержит кастомный слой интеграции для сайтов на Bitrix Framework.
Код написан по стандартам PSR-12, покрыт тестами и готов к развертыванию через CI/CD.

## 📁 Структура проекта

Вся разработка ведется в директории `/local`, согласно официальной документации 1С-Битрикс.
- `local/php_interface/classes/` — бизнес-логика и классы интеграции.
- `local/php_interface/init.php` — точка входа (автозагрузка, подключение событий).
- `local/php_interface/events.php` — обработчики событий ядра.
- `local/logs/` — файлы логов.

## 🎯 Бизнес-задача
Автоматизация обмена данными между сайтом (БУС/Б24) и внешними системами (1С, платежные шлюзы, службы доставки).
Исключение ручного труда менеджеров, защита от дублей заказов и безопасное хранение API-ключей.

## 📦 Архитектура модулей (`local/php_interface/classes/Training/`)

### 1. `Integration/HttpClient.php` (Транспортный слой)
**Зачем нужен:** Безопасная отправка HTTP-запросов во внешние API (1С, ЮKassa и т.д.).
**Бизнес-ценность:**
* Защищает от утечки API-ключей (запрещает автоматические редиректы на чужие сайты).
* Предотвращает «зависание» сайта при недоступности внешнего сервиса (настраиваемые таймауты).
* Скрывает секретные данные (токены, пароли) из логов ошибок.

### 2. `Integration/ServiceRequestClient.php` (Бизнес-логика)
**Зачем нужен:** Управление бизнес-операциями (например, создание заказа в 1С).
**Бизнес-ценность:**
* Защищает компанию от дублирования заказов (использует `externalId` и `Idempotency-Key`).
* Умеет «сверять» статус заказа (`reconcile`), если связь оборвалась в момент отправки. Менеджер не потеряет заказ.
* Валидирует данные перед отправкой, чтобы не грузить мусором внешнюю систему.

### 3. `Config/Environment.php` (Управление окружениями)
**Зачем нужен:** Переключение настроек между средой разработки (dev) и боевым сервером (prod).
**Бизнес-ценность:** Позволяет безопасно тестировать код на тестовом шлюзе ЮKassa или 1С, не рискуя реальными деньгами и данными клиентов.

### 4. `Config/Logger.php` (Логирование)
**Зачем нужен:** Запись действий интеграции в файлы.
**Бизнес-ценность:** Безопасность. Автоматически заменяет пароли и секретные ключи на звездочки (`sh****45`) при записи в лог, чтобы они не украли злоумышленники.
